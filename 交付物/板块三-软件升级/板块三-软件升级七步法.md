## 第 3 步 · 确定方向 → 优先级矩阵

**双维度**：纵轴 = 用户痛点程度 ↑ ｜ 横轴 = 合规 / 安全要求 →

```
        高痛
         │  ★ 优先做              🔴 必须做
         │  (高痛·低合规)         (高痛·高合规)
         │  画布体验/排班预审      机构准入/资质核验/首诊拦截
         │                        知情同意/电子签名/加密等保
   ──────┼──────────────────────────────────────→ 高合规
         │  💤 暂不做              🟢 安排做
         │  (低痛·低合规)         (低痛·高合规)
         │  美颜/虚拟背景          留痕审计/境内存储/协议
         │  智能纪要自动生成        录制受控/应急质控
        低痛
```

| 象限 | 功能点 | 处置 |
|---|---|---|
| 🔴 **必须做**（高痛+高合规） | 机构准入、资质核验、首诊拦截、知情同意、电子签名、加密+等保三级、处方解耦 | V1 立即做 |
| ★ **优先做**（高痛） | 一体化协同画布、弱网音视频、授权调阅、MDT 预审 | V2 重点做 |
| 🟢 **安排做**（高合规） | 全程留痕审计、境内存储、服务协议、录制受控、应急质控、超范围拦截 | V2/V3 随版补强 |
| 💤 **暂不做** | 美颜、虚拟背景、智能纪要自动生成 | V3 标杆版 |

**排序铁律（任何项目成立）**：
1. 合规硬性要求 → 2. 安全漏洞修复 → 3. 高频痛点解决 → 4. 效率提升 → 5. 锦上添花
> **美观和体验永远排最后。**

## 第 4 步 · 设计功能 → 四件套

### ① 用户故事（复用三段式，一句话说清）

> 作为 **【发起方临床医生】**，我希望 **【在发起会诊时一键邀请多位专家并自动建立音视频房间】**，以便 **【快速组建会诊团队、减少会前等待】**。
> 验收：单场支持 ≥ 5 方；房间建立 < 10 秒；邀请状态（已接受/忙线/超时）实时可见。

（完整 16 条见《用户故事集》，四件套此处仅示范核心条目。）

### ② 功能清单（拆成 F1–F5 可执行任务）

| 编号 | 功能 | 所属模块 | 优先级 | 验收要点 |
|---|---|---|---|---|
| **F1** | 会诊工单列表与状态机（待受理→已受理→进行中→待签署→已归档） | 协同 | 🔴 必须做 | 状态可视化 + 异常告警 |
| **F2** | 音视频房间与邀约（组会/通知/弱网自适应） | 音视频 | 🔴 必须做 | ≥5 方、<10 秒、丢包 20% 可用 |
| **F3** | 病历/影像授权调阅与脱敏（最小必要 + 会话级临时授权） | 病历 | 🔴 必须做 | 敏感字段默认脱敏、越界告警 |
| **F4** | 结构化会诊记录与电子签名（模板 + 分区署名 + 签署归档） | 记录 | 🔴 必须做 | 关键字段强制、签署后方可归档 |
| **F5** | 全链路存证与审计（日志仅追加 + 审计导出） | 合规 | 🔴 必须做 | 日志 ≥ 6 月、可导出 |

### ③ 页面原型（复用板块二布局方法）

见 [`README.md` 第 4 节](../板块二-布局设计/README.md)：登录页 / 会诊工单列表（列表页）/ **会诊协同工作台（详情页·核心）** / 会诊记录详情与签署（表单页）。
骨架遵循**四层结构**（顶部栏 → 左侧导航 → 主内容区 → 底部状态栏）与**列表→详情→编辑三级钻取**。

### ④ 接口契约（新增哪些、旧接口改什么）

| 类型 | 接口 | 说明 | 关联 |
|---|---|---|---|
| 新增 | `POST /consultations` | 发起会诊单（校验机构准入 + 非首诊） | 红线1、红线3 |
| 新增 | `POST /consultations/{id}/invite` | 邀约专家（校验资质核验 + 知情同意） | 红线2、红线4 |
| 新增 | `GET /patients/{id}/records?scope=&fields=&ttl=` | 调阅病历（**新增字段级 + 时限级授权参数**，会话结束自动回收） | 红线8 |
| 新增 | `POST /consultations/{id}/sign` | 电子签名（签名与内容绑定、不可抵赖） | 红线6 |
| 新增 | `GET /audit/logs?from=&to=&actor=` | 审计日志导出（仅追加） | 红线9 |
| **改动** | `POST /consultations/{id}/archive` | 归档前**增加电子签名完整性校验**，未签署拒绝归档 | 红线5、红线6 |
| **改动** | 会诊意见 → 处方流转链路 | **切断**：会诊意见不得直接流转为处方 | 红线10 |

## 第 5 步 · 学习补缺（每个功能列三类缺口）

| 缺口类型 | 具体缺口 | 学习来源 |
|---|---|---|
| **业务缺口** | 会诊工单流转规则、MDT 排期逻辑、病历最小必要范围界定 | 《远程医疗服务管理规范》、中山一院 MDT 实践报告 |
| **技术缺口** | 音视频多方会议（弱网自适应）、DICOM 阅片 SDK、FHIR 接入层、时序存证 | WebRTC / 医学影像 SDK / HL7 FHIR 文档 |
| **合规缺口** | 电子签名法律效力、等保三级测评、脱敏与去标识化标准、日志留存 | 《电子签名法》、等保2.0、GB/T 39725-2020 |

> 原则：**先查文件再动手**——合规源都在公开规范里，先读文件再访谈，效率翻倍。

## 第 6 步 · 分步实施 → 三期迭代

| 版本 | 周期 | 目标 | 内容 | 对应差距 |
|---|---|---|---|---|
| **V1 基础版** | 1–2 周 | **补齐合规缺失（缺失即违规）** | 机构准入、资质核验、首诊拦截、知情同意、电子签名、处方解耦 | 6 项 🔴 严重缺失 |
| **V2 增强版** | 2–3 周 | **自动化 + 可视化** | 一体化协同画布、会话级细粒度授权、全程留痕审计、录制受控、境内存储 | 🟡 需升级 8 项 |
| **V3 标杆版** | 3–4 周 | **AI 辅助** | 智能纪要自动生成、时序绑定存证、FHIR 标准化接入、MDT 会前预审工作台 | 🟢 可改进 6 项 |

> **铁规矩：不要一次做太多**——三期模型让每步都有明确目标和可交付物。
