# 远程会诊平台 · 合规红线清单

**编制依据**：依据《医疗软件设计进阶四部曲》板块一——"合规是硬需求：先查红线，再问用户。需求分两层：用户层（痛点）靠访谈 + 合规层（红线）靠查文件。"红线来源 = 公开法规文件，先读文件再访谈，效率翻倍。

**用法说明**：逐条对号"已覆盖 / 设计中 / 缺失"。本清单为开发前初判，标注**建设状态**与**风险等级**，供排期与验收参考。

**核心原则（课程"三尊重"）**：尊重行业范式 · 尊重用户习惯 · 尊重合规红线。

## 三、重点红线解读（高优先）

- **"机构对机构"是远程会诊的底座**（红线 1、12）：平台不能把医生当作个人 C 端用户直接面向患者提供服务，必须以医疗机构为接入与责任主体，签署协议、明确责任划分。互联网医院场景下复诊等另行按规执行。
- **资质与首诊是两条不可逾越的线**（红线 2、3）：未通过资质核验的医师不得进入会诊；远程会诊不替代受邀方诊断、不开展首诊，系统应在流程上强制校验。
- **病历记录是合规的最终落点**（红线 5、6）：会诊记录的保存年限、书写规范、电子签名，决定了平台能否通过评审与法律追责——这也是《合规红线清单》与《用户故事集》US-REC 系列的直接对应点。
- **数据安全是"看不见的红线"**（红线 7、8、11）：等保三级、加密、脱敏、境内存储、出境管控，往往在出问题前无感，一旦出事即重大责任。
- **处方红线要前置拦截**（红线 10）：会诊模块与开方模块必须解耦，会诊意见不得直接流转为处方，避免违规开方。

## 四、合规建设优先级建议

排序铁律（来自课程）：**合规硬性要求 > 安全漏洞修复 > 高频痛点 > 效率提升 > 锦上添花**。

- **V1 基础版（先行）：红线 1/2/3/4/5/6/10/16 的流程性拦截与记录归档——机构准入、资质核验、首诊拦截、知情同意、病历规范、电子签名、处方解耦、超范围拦截，均为“缺失即违规”，必须最先落地；**
- **V2 增强版**：红线 8/9/12/13 的脱敏、审计留痕、责任协议化与音视频留存——系统性补强数据安全与举证能力；
- **V3 标杆版**：红线 14/15 的应急质量体系与网络质量保障。
- **上线闸门（不随版本分期）：红线 7（数据加密与等保三级）、红线 11（数据境内存储与出境管控）属于基础设施门槛，不按功能版本排期；V1 对外提供服务前必须完成等保三级测评与密评，否则不得上线。**
- **版本与风险等级一致性说明：红线 7、8、11、16 均为 🔴高 风险项。若把 7、11 放进 V2、16 放进 V3，会出现“V1 上线即违规”的逻辑漏洞。本版按“准入门槛（闸门）/ 功能版本（V1–V3）/ 标杆增强”三档重排，确保任一版本对外服务时，高风险红线均已闭环。**

**验收提示**：每一条红线都应在《用户故事集》中有对应可验收的用户故事；上线验证须包含"国标条款过检"与"数据安全（加密+留痕）"两项（对应课程"上线验证六查"）。
